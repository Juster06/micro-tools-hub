Matching rules, line counts & privacy

Keep the first occurrence exactly

Default matching is case-sensitive and whitespace-sensitive. Later matching lines are duplicates. Case-insensitive matching uses JavaScript’s native Unicode lowercase conversion on each comparison key; this is not full Unicode case folding or locale-specific matching. ß and ss stay distinct. Accents and combining characters are never stripped or normalized.

Whitespace & blank lines

Ignore surrounding whitespace uses JavaScript trim() for comparison only, including tabs and Unicode whitespace such as non-breaking spaces. Retained text is never trimmed. Blank means empty or whitespace-only by the same trim() rule; zero-width space is not blank. Remove blank lines runs before duplicate detection, so those removals are counted only as blanks.

With blank removal off, keep the first distinct blank line under the selected matching rules; additional matching blanks count as duplicates.

Line endings & counts

LF, CRLF and CR separate lines. Empty input has zero lines; each separator in nonempty input starts another line, including a trailing blank. Output uses LF. Counts describe retained logical records, so one retained empty line has an empty text result but a retained count of one. Copy and download are disabled when the result has no characters.

Deterministic sorting

Sorting is optional and happens after deduplication. Compare the selected keys lexicographically by UTF-16 code units, with earlier occurrences first for equal keys. This is a predictable alphabetical-style order, not locale-aware collation or natural numeric sorting. Original retained text is unchanged.

Local processing & limits

Limit: 100,000 UTF-16 code units. Larger input stays intact and shows an error. Your text is not uploaded, logged or stored. The page and Tailwind Play CDN styling may require network requests; text processing does not. Copy depends on browser permissions; downloads are UTF-8 .txt files.
