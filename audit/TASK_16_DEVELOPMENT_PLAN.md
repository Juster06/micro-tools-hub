# Task 16 — CSV Merger scope

Baseline: `61135c1111360a4867446bb3649996713460b44c`; 93 registered, 49 RELEASED, 0 TESTED, 0 READY, 43 PLANNED, 1 BLOCKED. PRs #26 and #27 were merged, deployed and publicly verified. Analytics consent concerns remain unresolved and outside this task.

CSV Merger appends records from multiple files; CSV Viewer displays one file, Column Extractor chooses fields, and Duplicate Row Finder filters rows. This task adds distinct functionality. Use the existing CSV Viewer state-machine parsing approach and formula-risk export escaping; no third-party runtime or paid service. Processing stays in browser memory; hosting and existing styling CDN remain separate network requests.

Input: 2–8 local UTF-8 files, at most 1 MiB per file and 4 MiB total; at most 500,000 UTF-16 units per decoded file. Comma-delimited CSV, optional UTF-8 BOM, quoted fields, doubled quotes, multiline fields, and CR/LF/CRLF normalized to LF within fields. At most 2,000 records, 100 columns, 20,000 cells and 10,000 UTF-16 units per field per file. At most 5,000 combined data records and 40,000 combined output cells. The output is limited to 2,000,000 UTF-16 units and 4 MiB UTF-8. Resource limits include the header where relevant.

The first file is the reference schema. Header names are compared exactly and in order, including case and whitespace; empty or whitespace-only names and duplicate exact names are rejected in every file. Mismatched length, reordered names, missing/extra names and ragged records are errors. Blank lines parse as one empty cell and therefore fail a multi-column schema; for a one-column schema they are retained as empty records. No input is silently rearranged or dropped. Output includes the header once, file order is user-controlled, and exported records use CRLF. Formula-risk cells beginning with tab/CR/LF or optional whitespace/control characters followed by =, +, - or @ receive a leading apostrophe, as in existing CSV tools; this intentionally changes such cells and is disclosed. Preview shows at most 20 data rows; the entire result is bounded before enabling download.

Native labeled file controls and reorder/remove buttons support keyboard use. Async file reads use revision checks so replaced selections cannot produce stale output. Reset releases selected files and results. Test normal, malformed, Unicode, quoted/multiline, empty/ragged, duplicate/empty/reordered headers, limits, formula-risk values, download/reset, stale async operations, keyboard and responsive layout. Use real Chromium and source-bound audits before TESTED; public release remains pending.
